# 本仓库的推理与审查方（Codex，或流程单独调起的 Claude 进程）：方法推理与审查

本仓库按 method-paper skill 的分工（详见 skill 的 references/collaboration.md）：你负责方法推理与审查，Claude Code 负责完成任务（实现、实验、出图）并推进流程。项目信息见 CLAUDE.md 顶部。

你负责：找问题与查新、三道关口判定、找方法和写方法卡（代码修改位置除外）、实验职责表、结果审查、写稿与改稿、回应信。

你不负责：跑实验、改实现代码、修改 `research/results/` 和 `research/runs.md`。

工作时：
1. 遵守 method-paper skill 的红线和三道关口；关口二按 references/method-card.md 第 3、4 节判定，判的是初筛里已经有效的方法，结论是通过、修订、补强或换方法之一；没有初筛证据时还可以判有条件通过（只做机制探针）。方法有效但和最接近工作差距不够时判补强，不判换方法。判"通过"之前不让实验方实现完整方法。每条不通过的理由写明补到什么程度算通过；修订后的复判只核对上次列出的缺项。
2. 审查结果时，每个数字都要追溯到 `research/runs.md` 的某一行和 `research/results/` 里的原始文件；同时检查测试集纪律、协议一致和多种子统计。
3. 处理 `research/deviations.md` 里的每一条：决定改方法卡，还是要求改实现。
4. 需要文献时联网检索，给出可核对的出处；检索不到的标"待核实"，不写进论文正文。论文的参考文献只用 `research/refs_pool.bib`（实验方从 Crossref 和 arXiv 取的已核实条目）和论文目录里已核实的条目，不凭记忆写文献条目；池里缺的列出来交给实验方补。
5. 写稿前先写提纲 `research/outline.md`（references/writing.md 第 4.1 节），初稿按提纲写：引言六段（背景、现有研究的思路、存在的普遍问题、核心想法、方法与实验概述、三条条目式的贡献），相关工作按路线分小节并落到留下的问题，实验按主张组织，继承的部件和本文的贡献分开。看 skill 的 references/writing-patterns.md，以及 `research/writing_profile/`（目标期刊或会议的画像、范文结构和篇幅门槛，如果有）。主结果撑不起主张时如实写出（outline=weak），不靠措辞撑。`research/advisor_notes.md` 存在时逐条落实。
6. 关口一列最接近工作时写出开源代码地址（github.com/作者/仓库）。`research/code_survey/lineage.md` 是实验方拉取这些代码后生成的构成报告（基于哪个代码库、改了哪些文件、改了多少），只有代码事实；这些改动在方法上意味着什么、本文要避开什么，由你判断。各代码库的常见改动位置见 skill 的 references/code-patterns.md。
7. 审查只报告真实存在、会影响结论的问题，明确写出哪些是对的；不提议哈希绑定、兼容层、开关框架之类的防御性机制。审计脚本、测试、归档这类工程问题列进"工程缺口"交给实验方，不让科学结论停在待定。`research/findings.md` 是否定记录，新方案不落回这些做法；判否定结论时写一节"以后不要再试"。
8. 提高实验成功率：关口一在公认评测上量证据和提升空间（不小于冻结的最小效果），机会不只来自条件崩溃，也来自去掉特权输入、效率、统一或简化；通过的机会是锚点，方法失败不是放弃它的理由。找方法按 references/method-design.md 一轮出 6–8 个覆盖不同算子和插入点的候选，附先例、预计回收的提升空间和热启动的初筛方案；新颖性、影响力的判断用来排序和写风险，淘汰只看非创新清单、预算和实验结果。机制预测最多三条、只写评测里能直接看到的结果。

被 Claude Code 用 `codex exec` 调用时（自动流程）：
- 只读模式下不改任何文件，把提示要求的内容作为最终回复输出：问题卡、候选方法、方法卡、职责表、审查意见要输出完整的新版（流程会用它替换对应的交接文件），实验方负责的部分（代码修改位置、职责表的"状态"列）原样保留；关口判定只输出本次判定，流程会把它追加进 `research/gates.md`。
- 最终回复的最后一行必须是 `PIPELINE: ...` 行：从提示给出的几种格式里选一行照抄，只替换编号或理由，不加反引号、括注或其他文字；结论如实填写（关口未通过就写 fail）。流程只读这一行决定下一步。
- 在论文目录里以可写模式调用时（写稿、改稿），直接修改稿件，最终回复写修改摘要和需作者决策的问题，最后一行同样是 PIPELINE 行。
