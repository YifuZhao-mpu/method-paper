# 方法卡（关口二）

方法卡是内部工作文档，作用是逼出"新东西到底是什么"。它和论文方法节的区别只有一个：方法卡里有代码修改位置，论文里没有。

## 0. 从机会到方法

方法从关口一通过的机会（锚点）出发，按 [method-design.md](method-design.md) 走：一轮出 6–8 个覆盖不同算子和插入点的候选，排序后把前几个做成最小版本初筛，接近的细化、有效的叠加，最后只为初筛胜者写方法卡。

想候选时可以沿失效链逐环找切断点，每一环对应几种算子：
- 被违背的假设来自表示：换表示；
- 出错的是某个计算环节：去近似或精确化、联合求解或可微化；
- 欠约束或监督不足：先验或约束、新监督来源或蒸馏；
- 测量质量不均：不确定性或可靠性、自适应分配；
- 依赖拿不到的输入：去掉特权输入（用估计值替代，并对估计误差稳健）。

排序时优先：直接针对根因（而不是补偿症状）、对一类问题成立、能插进多个基线、推理代价可接受、有同类做法在相邻问题上奏效的先例。这些是排序标准，不是淘汰条件；淘汰只看非创新清单（第 3 节）、预算和初筛结果。

## 1. 七要素

| 要素 | 要写到什么程度 |
|---|---|
| 输入输出 | 符号、形状（如 B×N×C）、坐标系与单位、来自哪个环节、输出给谁 |
| 计算过程 | 分步骤写，每步对应一个公式或算子 |
| 数学定义 | 完整公式；新引入的量全部有定义；与已有符号不冲突 |
| 与原流程的连接方式 | 插在哪里、替换什么、与哪些特征或变量交互、是否共享参数、推理时是否保留 |
| 训练或优化目标 | 总损失 = 原损失 + λ·新损失；新损失的定义、监督来源、λ 的设定方式；训练流程是否改变（分阶段、冻结哪些参数）。不涉及学习的方法写优化目标或判定准则 |
| 伪代码 | 10–25 行，变量名与公式符号一致 |
| 代码修改位置（内部） | 仓库、文件、类或函数、改动类型（新增、替换、插入调用）。先读代码库再写，不凭空编文件名；不进入论文正文 |

另外几项必须写：

- **初筛证据**：初筛的设置、数字和对照（同步训练的基线、等容量对照或去掉关键项），出自 research/screen.md 和 runs.md 的哪几行。初筛跳过时写明，关口二就只能判有条件通过（第 4 节）。
- **组件结构**：一个主贡献，加最多两个支撑组件；每个组件对应哪个算子，各自用哪个消融证明。
- **机制预测（最多三条）**：都写成评测里能直接看到的结果，例如增益集中在目标子集、去掉关键项增益消失、等容量对照复现不了；写明什么结果算落空。网络内部状态的分析不写成预测，放到关口三。
- **本质差异**：与最接近方法的区别，一句话说完。"用了不同的网络结构"不算区别，要说清计算上哪里不同、为什么这个不同能带来提升。
- **一般性**：适用的问题类、成立前提、可插入的基线范围。

## 2. 方法不要写窄

- **形态不窄**：方法不限于网络模块。新的表示、损失、采样策略、优化或推理算法、几何或物理模型、数据生成机制、控制策略，都可以是方法创新。七要素中对它不适用的项，写明为什么不适用，例如"无训练目标：该算子无可学习参数，作用于推理阶段"。
- **适用面不窄**：用问题类的通用语言定义方法，例如"对任意以球面观测为输入、以局部邻域聚合为核心算子的重建方法"，而不是"在某个数据集上加的修正"。成立前提写成机制条件，例如"观测存在非均匀立体角采样"，不写成数据集名单。能插进多个基线的，在实验里证明可插拔。

## 3. 不算方法创新（关口二判"换方法"）

- 只有命名（"XX-Net""XX 模块"），没有七要素；
- 调参，换优化器或学习率调度，加训练轮数；
- 加评价指标，加数据集，换 backbone，换预训练权重；
- 数据增强组合，除非增强本身是由失效机制推导出的新算子，并且给得出七要素；
- 现成模块拼接，却说不清为什么能消除失效机制；
- 后处理阈值规则，除非形式化成有定义、有目标的计算。

这些工作可以是好的工程，也可以出现在实验设置里，但不能被写成论文的方法贡献。

反过来，下面这些**算**方法创新，不能因此判不通过（与 NeurIPS、CVPR 审稿指南和 ARR 列出的"偷懒式审稿理由"一致）：
- 已有技术的新组合，只要组合的理由讲清楚、并且针对关口一的机会；
- 去掉特权输入：用新的计算替代真值、标定、已知位姿或标签，同样的任务达到接近的效果；
- 从相邻领域迁移过来的做法，迁移时做了非平凡的改动（写清改了什么、为什么必须改）；
- 几个算子叠加，每个组件都有消融证明自己的贡献；
- 用更简单或更精确的计算替换出错的环节（例如把近似换成精确计算、换一种表示让被违背的假设不再需要）；
- 由失效机制推导出的新损失、新正则或新监督，七要素写得出来；
- 改动量小。顶会接收的方法里，只改几百行、甚至只动 Python 层的并不少见（code-patterns.md 第 5 节）。

"太简单""事后看来显然""没有先例""不是 SOTA"都不是不通过的理由；"已经有人做过"必须给出具体的论文或代码，并指出重合的计算环节。

## 4. 关口二判定

关口二判的是已经在初筛里有效的方法，而不是纸面上的设想：方法卡只为初筛胜者写，判定时有数字可依。设计依据：会议的审稿指南按"接收理由与拒稿理由的权衡"下结论，容易改正的小问题不作为拒稿理由；阶段关口评审的结论分为放行、终止、暂缓、退回重做，不是只有通过和不通过。用大模型当评审时，"严厉审稿人"式的提示和"至少列 N 条问题"的要求会系统性地压低结论，所以拒稿理由只进风险清单，不直接决定结论。

**A. 完整性清单（必须全部满足，每项写满足或不满足及依据）**

| 项 | 满足的标准 |
|---|---|
| 七要素 | 齐全、互相一致；不适用的要素写明原因 |
| 初筛证据 | 初筛里达到事先写的判据，并且增益不是额外训练或参数量带来的：同步训练的基线、等容量对照或去掉关键项复现不了它。初筛跳过时写"无初筛证据" |
| 机制预测 | 最多三条，写成评测里能直接看到的结果，写明什么算落空 |
| 本质差异 | 与最接近工作的区别落在具体的计算环节，有出处；有代码构成报告时，代码修改位置和改动类型不与某个最接近工作基本相同 |
| 不在非创新清单 | 不属于第 3 节列出的情形 |

**B. 贡献判断（权衡，不逐条否决）**

列出接收理由和拒稿理由，按审稿指南的口径权衡：新组合、去掉特权输入、跨领域迁移、简单替换、改动量小都可以是新颖的；适用面窄只影响主张范围（缩小到成立的问题类），不单独构成不通过。按 method-design.md 第 8 节校准：先找 2–3 篇目标会议近两年、同方向、改动规模相近的接收论文作对照，按同样的标准它们也过不了，就是判得过严；本方向常见的算子，新颖性要落在具体计算或设定上。

**结论**

| 结论 | 条件 | 之后 |
|---|---|---|
| 通过 | A 全部满足，B 接收理由占优 | 写完整实验职责表 |
| 有条件通过 | 只用于没有初筛证据的方法：A 其余各项满足，B 接收理由占优 | 先做最小验证实验（experiments.md 第 3.1 节），预测得到支持再写完整职责表 |
| 修订 | 方法值得保留，A 有可补齐的缺项（写法、要素、预测） | 按缺项修订方法卡后复判，不回到找方法 |
| 补强 | 方法有效、不在非创新清单，但和最接近工作的差距不够撑起一篇论文 | 保留这个方法作主体，回到找方法给出 2–4 个加强方向（叠加另一个算子的支撑组件、换到去掉特权输入的设定、把近似换成精确计算等），以主体为对照初筛，达标的加强合进方法卡再判；加强都没达标时暂停由作者决定；最多两次 |
| 换方法 | 撞车（有具体出处，同一评测、同一计算环节、没有本质差异）；属于非创新清单；或者初筛的增益被对照复现（来自额外训练或参数量） | 带着原因重新出一轮候选 |

**写法要求**
- 每条不满足项都写明"补到什么程度算通过"；写不出通过条件的意见，放进风险清单，不作为不通过的理由。
- 修订后的复判只核对上次列出的缺项是否补齐、改动处是否引入新问题，不新增上次没提出、方法卡也没改动的意见。
- 审稿人可能的质疑列成风险清单：每条写能否化解、交给哪个实验或哪句主张范围。风险清单交给实验设计（关口三），不决定关口二的结论。
- 结论直接写，不用发布会原则软化（红线 3）。

未通过关口二（修订、补强、换方法）时不进入写作模式，也不实现完整方法；初筛的最小实现不算完整方法。有条件通过时只能做最小验证实验。

## 5. 写进论文：让读者读懂方法

- 方法节顺序：总览（一句话机制加框架图）→ 问题设定与符号 → 各模块 → 训练目标 → 推理流程 → 复杂度（可选）。
- 每个模块按同一节奏写：先一句它解决哪个不足（消除哪个失效、去掉哪个特权输入、省掉哪部分代价），再给定义公式，再写连接方式，最后一句直观解释。
- 公式后面紧跟直观解释；符号全文统一，并与框架图一致。
- 伪代码放正文还是附录，看篇幅。
- 用问题类的通用语言描述方法，成立前提写清楚。
- 不出现文件名、函数名、超参搜索过程，也不写"我们尝试过"。
- 方法节占全文篇幅最大的一块；实验数据只放能证明方法的部分。
