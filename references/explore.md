# 探索：找成立的机会（关口一）

目标是产出"问题卡"，而不是综述。综述性的内容只是中间材料，最后留下来的只有在公认评测上量得出来、修好它需要新计算的机会。四类机会、它们在接收论文里的比例和例子见 [method-design.md](method-design.md) 第 2 节。

## 0. 起点：定好基线和评测，列出四类机会

只在平均指标上调参、抠零点几的路过不了关口二。要找的是一个量得出来、修好它需要新计算的不足，并且要在目标会议认可的评测上量出来。

1. **先定基线和评测。** 选一个近两年、代码能跑的强开源基线（code-patterns.md 第 3 节列了各方向的基础代码库），和目标会议认可的评测：公认 benchmark；机器人方向是仿真闭环 benchmark 或真机。之后所有候选都在这个基线、这个评测上量，所有方法都是这个基线代码上的改动。自建的诊断设置只用来找原因，不当主战场。
2. **按四类机会梳理候选（约半天）。**
   - 条件崩溃与泛化：论文的 limitation 段落和失败样例图、benchmark 的逐场景或逐类别结果（被平均值掩盖的差场景）、开源仓库的 issue、基线的最差视角或最差样本；
   - 去掉特权输入或监督：逐项列出基线在评测里用到、但实际部署拿不到或很贵的东西（真值高度或位姿、标定、标签、仿真特权信息、离线预处理），每一项都是一个候选；
   - 效率、统一或简化：基线最慢、最占显存、流程最长的环节；
   - 新能力或新设定：现有方法做不到、但有公开数据或仿真能评测的任务。
3. **写成候选清单，不写综述。** 每个候选写：机会类型；触发条件或依赖的特权输入；基线在评测上表现如何（有数字写数字）；证据来源；失效发生在哪个计算环节（作为假设，用来启发方法，不要求先证明）。
4. **先确认，再验证。** 列完候选先停下来，和作者确认要验证哪几个，再进入第 3 步量证据和提升空间、第 4 步撞车检查。
5. **每个候选都要能推出新计算。** 只能证明"效果差"、推不出新计算的候选不保留。

下面第 1、2 步为候选提供文献依据，第 3、4 步逐个验证。

## 1. 领域四角度梳理

对用户给定的领域，从四个角度梳理还有哪些值得深入的问题：

- **近几年研究趋势**：近 2–3 年主线怎么变（表示形式、监督方式、模型规模、传感器配置、评测方式）。
- **主流方法**：按技术路线分 3–5 类，每类给代表作，并写出这一类依赖的核心假设。
- **已有瓶颈**：每个瓶颈写成一个可观测的失效现象，并标注它是否已被广泛讨论。广泛讨论意味着竞争激烈，机会小。
- **未解决问题**：写明没被解决的原因，例如缺数据、缺评测、被平均指标掩盖、被默认假设掩盖、计算代价过高。

每条结论附代表文献。能联网就检索核实；不能联网时，把凭记忆写的内容标"待核实"，不编造文献。

## 2. 共同假设拆解（关键步骤）

选 5–10 篇核心论文（必须含近两年 SOTA），逐篇列出：

- **显式假设与隐式假设**：数据分布、几何与物理、时间同步、传感器特性、监督形式、计算预算、场景是否静态、观测是否完整等。
- **方法局限**：作者承认的和没承认的。
- **潜在遗漏**：没评测过的条件、被平均指标掩盖的子集、没报告的失败案例。

然后横向比较，找出**大家共享**的假设，逐条回答三个问题：它在什么条件下不成立？不成立时哪一步计算会出错？会表现为什么误差？答得出来的，就是候选突破口。

| 论文 | 共同假设 | 方法局限 | 潜在遗漏 | 突破口候选 |
|---|---|---|---|---|

几个常见的"共享假设"来源，供启发：局部邻域在投影后仍然局部（全景、鱼眼、球面数据常常不满足）；传感器之间严格同步、外参固定；点云密度均匀；场景静态；训练与测试的视角或物体分布一致；动作序列在时间上平滑；监督信号是干净的。

## 3. 机会是否成立（关口一的证据）

在第 0 步定好的基线和评测上，按机会类型量证据：

| 机会 | 最小证据 | 提升空间 |
|---|---|---|
| 条件崩溃与泛化 | 按条件分层（距离、遮挡率、投影畸变、视角变化、运动速度、接触或交接阶段、光照、噪声），误差随条件变差明显上升；或受控扰动；3–5 个典型失败样例 | 失效代价（失效条件下比正常条件差多少）和上限（把失效去掉后基线能到多少，例如给理想输入、真值标定、无畸变投影；做不到完全去掉就用最接近的版本并写明）中较小的那个 |
| 去掉特权输入或监督 | 同一设置下分别用特权输入和现实里拿得到的替代（估计值、噪声版本、去掉）跑基线 | 两者的差距 |
| 效率 | 基线的质量与代价（时间、显存、参数量）曲线 | 同等质量下代价能降的比例 |
| 统一或简化 | 多段流程各自的质量和总代价 | 一个模型达到同等质量时省掉的环节或代价 |
| 新能力或新设定 | 现有方法在公开评测上做不到或很差 | 上限（理想条件或人类、专家的表现）与现有方法的差距 |

提升空间要不小于论文打算主张的最小效果（例如 1 AP），把这个最小效果写下来冻结，之后的初筛判据、机制预测都按它折算。提升空间不够时判关口一未通过，或者把问题换到空间更大的评测设置里，而不是指望换方法补上。

另外三条：
- **失效的计算环节是假设。** 写下来用于启发方法，不要求先用受控实验证明；它在关口三用分层实验和消融去验证。
- **主战场是公认评测。** 诊断用的自建设置可以帮助定位，但提升空间要在之后报告主结果的那个评测上量。
- **锚点。** 通过关口一的机会成为锚点：之后方法没奏效不放弃它，只有提升空间被实验否定或作者决定才放弃（method-design.md 第 2 节）。

## 4. SOTA 撞车检查

检索最近 12–18 个月的工作（arXiv、顶会论文集、OpenReview）：

- 关键词检索，同时列出同一机制的不同叫法，逐个搜。
- 翻主基线论文的被引列表：同期工作常常换了说法，关键词搜不到，但几乎都会引用同一个基线。
- 看相关代码仓库和项目主页。

列出最接近的 3–5 篇，逐篇判断：未处理 / 部分处理（缺口在哪）/ 已处理。只有一篇具体的工作在同一评测上、用同类计算已经解决了同一个机会，而且效果相当时，才判已处理；其余情况写进风险和差异，不作为不通过的理由。

**无法联网时**：这一步不能算完成，关口一最多判"待补证据"。列出待检索的查询清单（关键词及其同义叫法、要翻被引列表的主基线论文、要查的会议和年份），交给作者或下一次能联网的会话完成。凭记忆列出的文献一律标"待核实"，只出现在内部材料里，不写进论文正文。

## 5. 交叉视角发散（用来打开思路）

把领域分别与下面几个视角结合，各提出 1–2 个具体研究问题：因果推断、多模态学习、复杂系统、行为科学、可解释 AI。视觉、雷达、机器人方向再加几个视角：几何与物理先验、控制与动力学、信息论与压缩、优化与数值稳定性、信号处理（采样、频谱、噪声模型）。

每个问题立刻用第 3 步的标准过滤：没有可观测失效现象的问题不保留。

## 6. 审稿人质疑

以顶刊顶会审稿人的身份质疑研究方向的创新性，给出**至少 10 条**可能的拒稿理由，覆盖：新颖性（已有工作、增量改进）、问题重要性、方法合理性、实验公平性（基线、协议、调参预算）、泛化性（数据集或场景单一）、机制解释（为什么有效）、效率代价、复现性、与 SOTA 的差距、写作清晰度。

每条写明能否通过方法或实验化解、怎么化解；化解不了的列为风险。这一步是内部材料，措辞要尖锐，不留情面。这些质疑进风险清单，用来给候选排序和设计实验，不单独作为否决候选的理由。

## 7. idea 拆解

把通过筛选的 idea 拆成七项：研究问题、核心假设（必须可证伪）、方法设计（转入方法卡）、数据需求（优先公开标准 benchmark）、实验方案（转入实验职责表）、预期贡献（2–3 条，每条都能被一个实验验证）、潜在风险及应对。

## 8. 问题卡模板与好问题的标准

**问题卡**

- 机会类型：条件崩溃与泛化 / 去掉特权输入或监督 / 效率 / 统一或简化 / 新能力或新设定。
- 一句话：在【条件或依赖】下，【基线】在【评测】上【掉多少 / 慢多少 / 做不到】。
- 基线与评测：基线代码（github 地址）、benchmark 或评测方式、指标。
- 证据：文献……；初步实验……（分层结果或特权差距）。
- 提升空间：失效代价、上限（或特权差距、代价比例）的数值；冻结的最小效果。
- 计算环节假设：失效发生在哪一步、为什么（假设）。
- 最接近的工作与差异：……
- 重要性：影响哪些任务和场景。
- 为什么别人没注意到：被平均指标掩盖 / 默认假设 / 评测都用了特权输入 / 缺少评测。
- 关口一结论：通过（成为锚点） / 未通过 / 待补证据（缺什么，下一步做什么）。

**好问题的标准**

- 不足在公认评测上量得出来，提升空间不小于冻结的最小效果；
- 解决它需要新的计算，而不是更多数据或调参；
- 解决方式对一类问题成立，而不是只对一个数据集成立；
- 最近的 SOTA 没处理，或处理方式有明确缺口。
