## 1. 发布会原则

论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。

1. 只围绕本文最强的优势组织叙事，不构成优势的内容不进主线；
2. 不按"我们做了什么、试过什么、哪些失败了"的过程写，只保留最终成立的逻辑：问题为什么重要 → 现有方法为什么不够 → 本文提供了什么 → 证据如何支持；
3. 禁止自我削弱表达（"遗憾的是""仅""仍明显落后""效果有限""存在严重不足"），不替审稿人总结弱点，不把局部现象写成普遍缺陷；
4. 打不过的指标不设为比赛项目，换评价维度、应用场景或比较口径，明确本文赢的是哪一场比赛；
5. 不占优的结果不说输：先判断是否必须讨论，再从目标差异、约束条件或合理权衡解释，或收缩主张避免正面对撞；
6. 优势必须主动说清楚：本文在什么条件下最好、优势为什么出现、解决了什么实际问题，别指望审稿人自己从表格里发现；
7. 每个实验必须承担明确论证职责（证明有效 / 证明关键机制 / 证明场景价值 / 排除替代解释），不承担职责的实验删掉或重新设计；
8. 摘要和引言像发布会开场：重要问题 → 现有缺口 → 本文思路 → 最硬的结果，不从实现细节和过程开始；
9. 结论只强化记忆点，不在最后突然加入新的自我否定。

遇到不理想的材料，按优先级处理：删除 → 缩小主张 → 换评价维度 → 解释为权衡 → 重组实验 → 重新定义故事。只有无法回避且影响核心结论时，才做必要说明。

## 2. 内部材料与正文的边界（诚信边界）

发布会原则管的是"怎么讲"，不改变"证据是什么"。下面几条是它的使用边界，改稿时和发布会原则同等优先：

- **内部材料照实说。** 发布会原则约束的是论文正文。关口判定、审稿人质疑、风险清单、问题表里的"理由"列都是内部材料，照实直说。
- **删措辞，不删结果。** 改稿者可以删的是削弱性措辞和不承担论证职责的叙述。删除实验结果（表格的行或列、数据点、整组实验）一律列入"需作者决策"，由作者判断它是否影响核心结论；影响核心结论的不利结果走"缩小主张"或"必要说明"，不能删掉证据却保留原主张。
- **"不说输"指口吻，不指事实。** 不用失败者的口吻，不等于隐瞒差距：差距照实给出数字，口吻中性。原因只写稿件里已有的、或作者提供并有证据支撑的解释，改稿者不替作者补原因。
- **对冲词按证据去留。** 去掉"在一定程度上""可能"的前提，是有直接证据（对应的消融、分层实验或统计检验）。证据只支持相关、不支持因果时，保留限定，或改成与证据相称的说法（如"与……一致"），不能靠删词把相关写成因果。
- **改法不引入新事实。** 改法只能使用稿件已有的事实和作者提供的信息。需要新增的原因、数字、比较对象、比较口径，用【】占位，并列入"需作者决策"。
- **标准指标照常报告。** "打不过的指标不设为比赛项目"不等于不报告。benchmark 惯例要求的标准指标照常列在表里，缺了反而会引起审稿人怀疑；只是叙事的主战场放在本文赢的维度上。
- **换口径要公平。** "换比较口径"只能换成同样公平、在文中写明的口径，例如同等参数量、同等延迟、同等训练数据、特定困难子集；不能换成只对本文有利、对基线不公平的设置。
- **文献不凭记忆进正文。** 无法联网检索时凭记忆写出的文献只能留在内部材料里，并标"待核实"；写进正文的每条引用都要核实过作者、题目、年份和出处。
- **limitations。** 目标会议要求 limitations 小节时（例如 NeurIPS 的 checklist），写成"适用条件与扩展方向"，篇幅短，不否定核心结论。

## 3. 文风规则

1. **正文不出现疑问句**，包括设问和反问。需要引出问题时用陈述句，例如"X 的关键在于……"。
2. **整段叙述。** 同一个论证写成一个完整的段落，用"因此、由此、在此基础上、相比之下、具体而言"等词衔接，不拆成条目式的分段描述。引言末尾的贡献点是唯一可以用列表的地方；作者偏好整段时，贡献点也写成一段。
3. **正文不出现文件名**、路径、代码里的变量名或函数名、实验编号、版本号。需要指代实现时，用方法中的符号或模块名。
4. **参考文献顺序从上到下从小到大。** 按首次引用顺序编号，正文中的引用编号从上到下递增出现；同一处引用多篇时按升序排列并压缩，例如 [3–5, 8]。这条适用于按引用顺序编号的模板（IEEE 系的 RA-L、ICRA、IROS，多数期刊，学位论文）。CVPR、ICCV、ECCV 的官方模板默认按作者字母排序，正文编号本来就不会从小到大，这时以模板为准，只要求同一处多篇引用按升序排列，并提醒作者。
5. **逻辑清晰。** 每段首句是中心句，段内按"论点 → 依据 → 结论"展开，段与段之间有承接；同一概念全文用同一个术语、同一个符号。
6. **不混写改动前后的数据。** 正文和表格只呈现最终方法与命名清楚的消融变体，例如"w/o 某模块""某模块 → 普通卷积"；不出现"改动前/改动后""旧版/新版""第一版"。每个结论只基于同一配置下的结果，改进过程本身不是论文内容。
7. **摘要和全文都说清三件事**：提出的方法（名称加一句话机制）、解决的问题（失效机制）、得到的结果（最硬的数字及比较对象）。

## 4. 各部分写法

篇幅和结构的常态数字（摘要词数和句数、题目格式、引言段数、贡献点条数、实验规模）见 writing-patterns.md，写完对照第 11 节的检查清单。

**摘要**，像发布会开场：重要问题（1 句）→ 现有缺口，即失效机制（1–2 句）→ 本文思路，方法名加机制（2–3 句）→ 最硬的结果，具体数字、数据集、比较对象（1–2 句）→ 意义（可选，1 句）。不从实现细节或研究过程开始。

**引言**：
- 第 1 段，问题为什么重要：任务、应用和难点。
- 第 2 段，现有方法为什么不够：按技术路线概括，落到具体的失效机制，给出证据（可以配合 Fig. 1 展示失败样例）。
- 第 3 段，本文提供了什么：核心 insight 和方法概述，讲清它为什么能消除失效机制。
- 第 4 段，证据与贡献：最硬的结果，以及 2–3 条贡献，每条贡献都能对应一个实验。

**相关工作**：按技术路线分组，每组末尾用一句话说明与本文的本质差异，不写成文献罗列。

**方法**：总览（一句话机制加框架图）→ 问题设定与符号 → 各模块（消除哪个失效 → 定义公式 → 连接方式 → 直观解释）→ 训练目标 → 推理流程 → 复杂度（可选）。符号全文统一，并与框架图一致。用问题类的通用语言描述方法，把成立前提写清楚。读者读完方法节应能复现。

**实验**：设置（数据集、指标、实现细节、对比方法，一段写完）→ 主结果（先写结论，再引表）→ 机制验证（消融、区分性实验、困难场景分层）→ 鲁棒性与效率 → 可视化。每个小节的首句写明这个实验证明什么。

**结论**：重申问题、方法、最硬的结果和意义，强化记忆点；不新增实验结论，不新增自我否定。

## 5. 防御性写作审查

### 5.1 类型

| 代号 | 类型 | 典型表达 | 对应规则 |
|---|---|---|---|
| A | 自我削弱 | 遗憾的是、仅、只、仍明显落后、效果有限、存在严重不足、略逊于、未能、无法完全、不可避免地；unfortunately, only, merely, still lags behind, limited improvement, fails to, cannot fully, slightly worse | 原则 3 |
| B | 过度对冲（有直接证据时才去掉，见第 2 节） | 在一定程度上、可能、或许、似乎、初步、尝试、有望；to some extent, may, might, seems, attempt to, preliminary, potentially | 原则 3、6 |
| C | 替审稿人总结弱点 | 需要指出的是本方法……不足；本文方法存在以下局限 | 原则 3 |
| D | 局部现象写成普遍缺陷 | 某个场景表现低，写成"本方法在……方面表现较差" | 原则 3、5 |
| E | 过程叙述 | 我们首先尝试、经过多次实验、后来发现、最初的版本；we first tried, after several attempts, initially | 原则 2 |
| F | 劣势指标被设为比赛项目 | 在不占优的指标上逐项比较并承认落后 | 原则 4、5 |
| G | 优势没说清 | 只给表格，不解释赢在哪、为什么赢、在什么条件下最好 | 原则 6 |
| H | 结论处新增自我否定 | 结论或最后一段突然列缺点 | 原则 9 |
| I | 改动前后混写 | 改动前/改动后、旧版/新版、v1/v2 的数据并列 | 文风 6 |
| J | 文风违规 | 疑问句、条目式分段、文件名、引用编号乱序 | 文风 1–4 |

注意语境：描述**已有方法**的失效（"现有方法无法处理……"）是在讲缺口，不是防御性写作；"仅需 3 ms"这类强调优势的"仅"可以保留。审查的对象是对**本文方法**的削弱。

### 5.2 流程

1. 跑 `scripts/paper_lint.py` 做初筛。
2. 逐句语义审查，按 A–J 标注。
3. 每处给出改法，遵守最小改动：保持作者的用词习惯和段落结构；优先删去削弱成分、替换一个词、或调整一句比较口径；不整段重写；不改数据和事实；没有问题的部分不动。改法遵守第 2 节：删措辞不删结果，不引入新事实，对冲词按证据去留。
4. F、G 类和所有涉及删除结果的问题，单列为"需作者决策"，按处理优先级给出建议。

### 5.3 输出格式

| 编号 | 位置 | 原文 | 类型/规则 | 改法（改后的完整句子） | 理由 |
|---|---|---|---|---|---|

"理由"列是给作者的内部说明，可以直说。表后附"需作者决策"清单，最后给出修改后的全文或修订文件。

### 5.4 改写示例（最小改动）

示例中【】里的数字是占位符，改稿时只能填稿件里或作者提供的实测值，不能编造。

| 原文 | 改法 | 说明 |
|---|---|---|
| 本方法仅提升了 0.8 dB。 | 本方法提升了 0.8 dB。 | 删去"仅"（A） |
| 该模块在一定程度上缓解了遮挡带来的漏检。 | 有对应的消融或分层结果时：该模块缓解了遮挡带来的漏检，重度遮挡子集上的召回率提升【实测值】。没有直接证据时：保留原句，或改为"与遮挡漏检的减少一致"。 | 对冲词按证据去留（B、G） |
| 我们首先尝试直接拼接两种特征，但效果不佳，因此提出了几何对齐模块。 | 直接拼接两种特征效果不佳，为此本文提出几何对齐模块。 | 删去过程叙述，只保留原句已有的事实（E）；要写出拼接为何不佳，原因由作者提供，先用【原因】占位 |
| 虽然本方法的推理速度略低于 A，但精度更高。 | 本方法的推理时间比 A 多【实测值】ms，mAP 高【实测值】。 | 写成权衡，代价和收益都给实测数字（A、F） |
| 遗憾的是，本方法在夜间场景中效果有限。 | 是否保留这个结果列入"需作者决策"。保留时去掉削弱措辞、照实给数字："本方法在夜间场景中的【指标】为【实测值】，基线为【实测值】。"原因只写作者提供并有证据的解释。 | 删措辞不删结果，不替作者补原因（D、原则 5） |
| Unfortunately, our method still lags behind X on metric Y. | Our method obtains [measured value] on Y, compared with [measured value] for X. 如果作者确认 X 使用了额外的 Z，再补一句 "X additionally uses Z." | 去掉削弱措辞，差距照实给出；比较口径上的事实由作者确认（A、F） |
| 本文方法存在以下不足：……（结论段） | 删除；需要时改为一句扩展方向："未来工作将把该机制扩展到……" | 结论不新增自我否定（H）；这些不足若影响核心结论，正文中要有对应的必要说明 |

## 6. 全文通体检查清单

逐项给出"通过 / 不通过 / 不适用"和位置：

- 发布会原则 1–9；
- 文风规则 1–7；
- 关口二七要素在方法节是否可见（输入输出、计算过程、公式、连接方式、训练目标、伪代码；代码修改位置不进正文）；
- 每个实验的论证职责是否明确，有没有不承担职责的实验；
- 摘要三件事；
- 图表（见 figures.md）：字号与正文接近且全文统一、字体一致、文字不遮挡线条和内容、矢量格式、无 Type 3 字体、同一方法同一颜色、表格为三线表、最优结果加粗；
- 引用编号顺序。

输出按严重程度分组：必须改（影响接收）/ 建议改 / 可选。每条给出位置和最小改法。

## 7. 回复审稿意见

回应信的读者已经读过论文，手里有判断权。发布会原则在这里的用法是自信、具体、不辩解，但事实问题不回避。

- **结构**：开头一段致谢，并概括主要修改；然后逐条回应。每条先编号引用审稿意见，再给结论（已修改、已补实验、澄清），最后给证据（新结果、修改位置，例如第几节第几段、哪张表），每条单独成段。
- **事实问题直接认**：审稿人指出的数据错误、遗漏的对比、不准确的表述，直接承认并说明已经修改。"不说输"只管口吻，不能用来否认事实。
- **误解就澄清，不指责**：先说明原文哪里写得不够清楚导致了误解、已经怎样改写，再给出正确的理解。
- **要求补实验**：按模式 D 设计，写清这个实验回答了审稿人的哪个疑问、结果是什么。做不了的实验说明原因，给出替代证据，不承诺做不到的事。
- **新颖性质疑**：用与最接近方法的本质差异（一句话）加对比实验回应，不重复摘要。
- **正文同步**：每条回应都对应正文里的实际修改，修订稿中标出改动（颜色或 latexdiff）；回应信里出现的新结果，正文或补充材料里都要有。
- **篇幅与措辞**：遵守会议限制（例如 CVPR 的 rebuttal 限一页）；不用"我们认为审稿人误解了"这类对抗表达，也不用过度谦卑的套话。
